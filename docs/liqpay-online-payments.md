# Онлайн-оплати Webshop

У «Продажі → Webshop-замовлення» додано аналіз транзакцій, їхній розподіл за способом оплати, фільтр замовлень за наявністю спроби відповідного статусу та історію спроб у розгорнутому замовленні. Статус P2 не змінюється. Успішна повторна спроба робить оплату замовлення успішною, але попередня відмова лишається в історії.

## Налаштування сервера

- `LIQPAY_PUBLIC_KEY` — ідентифікатор потрібного магазину.
- `LIQPAY_PRIVATE_KEY` — лише серверний секрет, без `NEXT_PUBLIC_`.
- Формат `i_<Webshop ID>_<суфікс>` зіставляється автоматично: суфікси `st`, числові та буквені зберігаються як окремі спроби.
- Вибраний спосіб оплати сайту не обмежує зіставлення: платежі можуть бути і в замовлень із `cash`/`bank`.
- `payment.order_id` / `payment.liqpay_order_id` використовуються як явні відповідності. `system_ref` не є ідентифікатором транзакції.
- `LIQPAY_ORDER_ID_FIELD=id` або `order_num` — лише для підтверджених інтеграцій із точним, непереформатованим order_id. Для поточного сайту залишити порожнім.
- Група `o_` належить документам ERP; без явної відповідності до замовлення сайту вона не включається в його статистику. Зіставлення за сумою не виконується.
- Успішна транзакція не гарантує повної оплати замовлення. При відмінності суми успішних транзакцій від поточної вартості або валюти показується попередження про звірку.

## Джерело і межі

Використовується серверний read-only API `reports`, версія 7, SHA3-256. Архів читається в послідовних вікнах до 28 діб і кешується на 60 секунд. UI оновлюється за наявним інтервалом дашборду (15 хвилин) або кнопкою оновлення. Callback та постійне зберігання платежів поки не налаштовані.

Статистика обмежена датами створення транзакцій у вибраному архіві та замовленнями за фільтрами. Оплата, що створена поза цим періодом, не буде знайдена; це не повна довічна історія замовлення. Змінений статус старої транзакції залежить від того, що повертає архів LiqPay. Для повної історії потрібне постійне зберігання/синхронізація та підтверджена відповідність ID.

Суми різних валют не додаються. Частки способів оплати рахуються за кількістю успішних транзакцій. Масиви з повторним ID платежу зводяться до останнього стану; різні ID спроб лишаються окремими. Причини показуються з `err_code` та `err_description`, якщо архів їх містить, інакше явно вказано, що причина не передана. При відкритті історії кожна знайдена спроба уточнюється через `status` (кеш 60 секунд). Відповідь приймається тільки при точному збігу ID платежу й order_id, щоб нова спроба не підмінила стару. Якщо API не повертає причину і тут, потрібен callback або перевірка в кабінеті LiqPay.

Виплати компанії і суми часткових повернень не виводяться як вигадані нулі: для них потрібна окрема інтеграція фінансового реєстру. Сума `amount` поверненого платежу не є гарантованою сумою часткового повернення.

Після налаштування перевірити реальні успішну оплату, відмову з причиною, повторну спробу, повернення та зіставлення ID. Локальна відсутність ключів має показувати стан «LiqPay ще не підключено».

Документація: https://www.liqpay.ua/uk/doc/api/information/payment_archive?tab=1 і https://www.liqpay.ua/uk/doc/api/errors.
