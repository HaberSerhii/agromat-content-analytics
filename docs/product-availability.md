# Аналіз наявності товару

Одна SKU — одна унікальна картка каталогу (ID). Усі дати та межі місяців — Europe/Kyiv.

## Чотири показники

- Активні товари: останнє спостереження місяця, `statusId === 5` та `deleted === false`.
- Неактивні товари: лише SKU, що перейшли з активного в інший стан протягом цього місяця й залишаються неактивними в останньому спостереженні. Старі неактивні SKU не входять. Повернення в наявність прибирає SKU зі списку; повторне вимкнення додає знову. Кожен місяць починається з нуля.
- Активні акційні та неактивні акційні — ті самі правила з `isOnSale` у відповідному знімку.

Картки, помісячна таблиця, CSV, графік і списки по кліку використовують однакові множини товарів. Натискання кількості відкриває всі товари відповідного показника. Окремі +/− відкривають входи та виходи за спостереженими змінами статусу протягом місяця. Повторні переходи одного SKU відображаються окремими подіями. Для активних + включає також появу нових активних SKU. Зміна категорії чи акційності впливає на відфільтровані підсумки, але сама по собі не вважається вимкненням товару.

Попередній останній місячний знімок потрібний як початковий стан. Відсутні дні та SKU не вважаються вимкненнями. Якщо SKU пропущено в знімку, для наступного спостереження зберігається його останній відомий статус. Без детального початкового знімка вимкнення й зміни показуються як «—», а не як вигаданий нуль. Внутрішньоденні переходи між двома знімками не відновлюються.

## Фільтри та пошук

Категорії/бренди: OR усередині фільтра, AND між фільтрами. Акційність і класифікація беруться з кожного історичного знімка. Пошук виконується за поточним каталогом: ID, код, goodsRef, артикул, бренд, назва, категорія. Усі слова запиту мають бути присутні. Знайдені ID обмежують усю історію, графік, таблицю та списки. Назви, артикули й посилання в деталях доповнюються поточним каталогом; зниклі товари без метаданих показуються за ID.

## Графік та порівняння

Графік між картками та таблицею показує всі календарні дні вибраного місяця. За замовчуванням — активні товари, доступні всі чотири показники. Точки — останні щоденні спостереження; пропущені й майбутні дні порожні, лінія через пропуск не проводиться. Значення доступне по наведенню, натисканню та з клавіатури.

Помісячна таблиця показує % м/м до попереднього календарного місяця з тими самими фільтрами. Поточний незавершений місяць порівнюється з останнім спостереженням попереднього. За відсутності даних відсоток не розраховується. База 0 та значення 0 дають 0%; зростання з нуля має пояснення без відсотка. CSV містить кількості та порівняння.

## Зберігання та API

Після повної синхронізації записуються `$PRODUCT_SNAPSHOTS_DIR/availability-monthly/YYYY-MM.json` та `availability-daily/YYYY-MM-DD.json.gz`. Компактні щоденні знімки містять ID, статус, архівність/акційність і словники категорій/брендів. Вони зберігаються незалежно від ротації повних карток; включити обидві директорії в резервне копіювання. Запис атомарний; старі синхронізації не замінюють нові. Часткова пагінація не записує повного знімка.

Доступні повні старі знімки конвертуються послідовно в компактні щоденні. Немає вихідного спостереження — історію не вигадуємо. Обчислення обробляє один файл за раз.

`POST /api/products/availability` з `report: "movements"`, `month`, `count` (3/6/12), `categories`, `brands`, `promotion` (`all`/`promo`/`regular`), `query` повертає `months`, `previous` та `facets`. Кожен місяць містить `counts`, `changes`, `days`, `date`, `baselineDate`. `selection: { metric: active|inactive|promoActive|promoInactive, mode: total|added|removed }` повертає відповідні `products`. Деталі без необхідних знімків не підміняються поточним станом.

Старі низькорівневі формати `analysis: monthly|daily`, агреговані totals/preorder та previousYear залишені для сумісності API, але більше не використовуються цим інтерфейсом.
