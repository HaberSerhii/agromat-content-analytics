## Область и метод

Проверен опубликованный код карточек товаров, продаж, акций, маркетинга, веб-аналитики, поисковой аналитики, результатов обработки контента, CPO и аудита BigQuery. «Анализ цен конкурентов» исключён из анализа и плана изменений.

Проверены способы чтения и хранения данных, TTL, дедупликация параллельных запросов, объём ответов и жизненный цикл компонентов. На продакшне выполнены последовательные чтения нескольких API без принудительного обновления кешей. Данные покупателей и секреты в отчёт не включены.

Это не нагрузочный тест. Замеры через loopback показывают серверную задержку, но не время отрисовки в браузере пользователя. Первый запрос ниже означает первый контрольный запрос с указанным ключом, а не гарантированно полностью холодный процесс. Не все подразделы измерены запросами: для поиска, диагностик и некоторых отчётов выводы основаны на коде. Точный состав heap и причины удержания объектов требуют профилирования на следующем этапе.

## Измеренные факты

VPS: около 1,92 ГиБ RAM и 2 ГиБ swap.

- Перед развёртыванием RSS процесса Next.js колебался примерно от 1,14 до 1,30 ГиБ, ранее достигал около 1,46 ГиБ по VmHWM. Это память всего приложения; долю исключённого раздела и долю каждого кеша по этим значениям определить нельзя.
- После перезапуска и первичной проверки RSS был около 290 МиБ. После контрольных чтений — около 1,13 ГиБ; доступной памяти ОС осталось примерно 231 МиБ. Другие запросы и фоновые задачи не изолированы, поэтому весь прирост нельзя приписать контрольным чтениям.
- У Redis зафиксировано около 226 МиБ логических данных, peak около 495 МиБ. `maxmemory=0`, policy `noeviction`: бюджет памяти не установлен. RSS Redis может быть меньше логического объёма, в том числе из-за swap.
- На диске есть кеш продаж, около 43 МиБ для используемого `sales-rows-v3.bin`; несколько предыдущих/других версий также занимают диск. Их размер не равен расходу RAM.

## Предложенная последовательность

Первый пакет: 1 → 2 → 3 → 4 → 5, плюс перенос lite-снимка из пункта 6. Затем 6–7 и бюджет Redis (12). Второй пакет: 8–11 по повторным замерам.

Критерии приёмки согласовать перед реализацией:

- Все показатели, сегменты, каналы, периоды сравнения и исключения услуг/возвратов совпадают с текущими расчётами на контрольных наборах.
- «Кошики» работают на текущем объёме без снятия защитного лимита ради полной выгрузки в RAM.
- Помесячная таблица получает один компактный отчёт вместо 12–24 запросов общего дашборда.
- Прогретые отчёты не обращаются к upstream без необходимости; после рестарта используют сохранённые валидные агрегаты.
- Общий размер кешей ограничен; смена фильтров не приводит к неограниченному удержанию памяти.
- Для одного согласованного сценария без конкурентов ориентир RSS Next.js ≤900 МиБ и доступной памяти ОС ≥300 МиБ. Это предлагаемые цели, а не обещанная экономия: уточнить после профилирования.
- Сравнивать медиану и p95 на одинаковом сценарии до/после, включая время интерфейса, а не только loopback API.

Изменения оптимизации, конфигурации Redis, форматов хранения и расписаний ожидают отдельного решения владельца проекта.
